## 핵심 용어 — 매개변수 vs 실인자

C++은 두 용어를 엄격히 구분한다. 혼용하면 참조 전달·주소 전달 개념에서 혼란이 생긴다.

| 용어 (한) | 용어 (영) | 정의 | 위치 |
|---|---|---|---|
| **매개변수** | Parameter / Formal Parameter | 함수 **정의·선언부**의 변수 | `int foo(int x, int y)` |
| **실인자** | Argument / Actual Parameter | 함수 **호출부**에서 전달하는 값 | `foo(6, 7)` 의 6, 7 |

```cpp
int foo(int x, int y);   // x, y → 매개변수 (Parameter)

foo(6, 7);               // 6, 7 → 실인자 (Argument)
foo(a, b + 1);           // a, b+1 → 실인자 (Argument)
```

> **스코프(Scope)와 수명(Lifetime)**: 매개변수 x, y는 함수 `{}` 블록 안에서만 유효하며, 함수 종료 시 스택에서 소멸된다. `// x and y are destroyed here` 주석이 이를 정확히 표현한다.

## 함수 프로토타입과 정의의 차이

오늘 코드에서 중요한 패턴: 함수 정의 전에 호출하기 위한 **전방 선언(Forward Declaration)**.

```cpp
int foo(int x, int y);   // 프로토타입 (선언) — 세미콜론 필수
                         // 컴파일러에게 "이 함수가 존재함"을 미리 알림

int foo(int x, int y)    // 정의 (본문 포함)
{
    return x + y;
}
```

| 구분 | 세미콜론 | 본문 | 목적 |
|---|---|---|---|
| **프로토타입 (선언)** | 필수 | 없음 | 컴파일러 사전 인지 |
| **정의** | 없음 | 있음 | 실제 동작 구현 |

**함수 시그니처(Signature)**: 함수 이름 + 매개변수 타입 목록. 반환형은 시그니처에 포함되지 않는다. 오버로딩은 시그니처가 달라야 가능하다.

## 값에 의한 전달 — 복사의 원리

**값에 의한 전달(Pass by Value)** 은 실인자의 **값을 복사**해 매개변수를 초기화한다.

```cpp
void doSomething(int y)
{
    cout << "In func " << y << " " << &y << endl;
}

int x = 6;
doSomething(x);   // x 자체가 아닌, x에 저장된 값 6이 복사됨
```

내부적으로 일어나는 일 (개념적):

```
doSomething(x) 호출 시:
  1. x의 값 6을 읽는다
  2. doSomething의 스택 프레임에 'int y'를 새로 생성한다
  3. y에 6을 복사하여 초기화한다  → int y = 6; (별도 메모리!)
  4. 함수 실행
  5. 함수 종료 → y 소멸, x는 그대로 6
```

> Python 등 다른 언어는 이 복사 과정을 완전히 숨긴다. C++은 이를 명시적으로 드러내므로, 메모리 수준에서 동작 방식을 이해할 수 있다.

## 주소 출력으로 증명하는 복사

7.2 강의의 핵심 실험: **`&x`와 `&y`를 직접 출력해 두 주소가 다름을 확인**한다.

```cpp
int x = 6;
cout << "In main " << x << " " << &x << endl;
// 출력: In main 6 0x0061FF1C

doSomething(x);
// doSomething 내부: cout << "In func " << y << " " << &y << endl;
// 출력: In func 6 0x0061FEF0   ← 0x0061FF1C와 다름!
```

```
[결론]
&x → 0x0061FF1C  (main 스택 프레임의 x)
&y → 0x0061FEF0  (doSomething 스택 프레임의 y)

두 주소가 다르다 → x와 y는 다른 메모리 위치 → 복사가 일어났음이 증명됨
```

> [!info] doSomething을 여러 번 호출해도 &y가 같은 이유
> 함수 호출마다 같은 레이아웃의 스택 프레임이 재생성된다. 이전 프레임이 해제된 자리에 새 프레임이 올라오므로 y의 절대 주소가 동일하게 보인다. 이것은 스택 메모리 **재사용**의 결과다.

## 세 가지 호출 패턴 — 리터럴·변수·표현식

```cpp
doSomething(5);       // 리터럴: 5 복사
doSomething(x);       // 변수:   x의 값(6) 복사
doSomething(x + 1);   // 표현식: 평가 결과(7) 복사
```

| 호출 | 실인자 종류 | 전달되는 값 | lvalue / rvalue |
|---|---|---|---|
| `doSomething(5)` | 정수 리터럴 | 5 | rvalue (주소 없음) |
| `doSomething(x)` | 변수 | x에 저장된 6 | lvalue (주소 있음) |
| `doSomething(x + 1)` | 산술 표현식 | 평가 결과 7 | rvalue (주소 없음) |

**lvalue vs rvalue**:
- **lvalue**: 메모리 위치를 가진 식 — `&x`처럼 주소를 취할 수 있다
- **rvalue**: 임시 값 — 주소가 없다. `x + 1`은 변수에 저장되기 전 임시 연산 결과

> 값에 의한 전달은 lvalue·rvalue를 모두 수용한다. 어떤 경우든 **값을 복사**하기 때문이다.

## 값에 의한 전달의 장단점

### 장점

| 장점 | 설명 |
|---|---|
| **안전성** | 함수 내부 수정이 외부에 영향 없음 — 의도치 않은 부작용(Side Effect) 방지 |
| **예측 가능성** | 함수가 외부 상태를 바꾸지 않으므로 디버깅 용이 |
| **스레드 안전성** | 각 스레드가 독립된 복사본 → Race Condition 없음 |
| **함수형 순수성** | 부작용 없는 순수 함수(Pure Function)의 기초 |

### 단점과 이후 강의 연결

| 단점 | 설명 | 해결책 (이후 강의) |
|---|---|---|
| **복사 비용** | 큰 객체 복사 시 성능 저하 | 참조 전달 (`const T&`) |
| **외부 수정 불가** | 함수가 인수를 변경해 결과를 돌려줄 수 없음 | 참조 전달 / 주소 전달 |

> 교수님이 강조하신 포인트: "y하고 x의 주소가 다르기 때문에, 함수 안에서 무슨 짓을 하더라도 밖으로 영향을 줄 수 없다. 코드가 복잡해지면 이게 가장 깔끔하다."

## 컴퓨터 구성 요소와의 연결 — 스택 프레임

값에 의한 전달은 **CPU 스택 메모리** 위에서 일어난다.

```
[doSomething(x) 호출 흐름]

1. x의 값(6)을 레지스터 RDI에 적재          ← 인자 전달 준비
2. CALL 명령: 복귀 주소를 스택에 push
             IP → doSomething으로 이동

3. doSomething 스택 프레임 생성:
   | saved RBP                      |
   | int y = 6  @ 0x0061FEF0       |  ← RDI의 값 6이 y에 복사됨

4. cout으로 y 값과 &y 출력
5. RET 명령: 복귀 주소 pop → IP 복원
   → doSomething 스택 프레임 해제, y 소멸

6. main 복귀: x는 0x0061FF1C에 6 그대로
```

| 하드웨어 | 역할 |
|---|---|
| **RAM (스택)** | y 변수가 x와 별도 위치에 할당됨 |
| **RSP** | 스택 꼭대기 추적 — 프레임 할당/해제 |
| **RBP** | 현재 스택 프레임 기준 주소 |
| **RDI** | 첫 번째 인자(x의 값 6)를 함수로 운반 |
| **ALU** | `x + 1` 계산 수행 |

> `int` 4바이트는 레지스터 하나에 들어가므로 복사가 레지스터 이동 1회로 완료된다 — 사실상 비용 없음. 큰 객체가 비싼 이유가 여기에 있다.
