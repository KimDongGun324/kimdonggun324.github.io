## 이 셰이더가 하는 일 — 전체 구조

오늘 분석한 GLSL Fragment Shader는 단 두 가지를 한다.

1. **배경**: `st.x`에 비례하는 회색 그라데이션 (왼쪽 검정 → 오른쪽 흰색)
2. **선**: 수학적 직선 `y = x`를 SDF 방식으로 그리고, 선형 보간으로 배경에 합성

```
픽셀 좌표 (gl_FragCoord)
    ↓ ÷ u_resolution
정규화 좌표 st ∈ [0,1]²
    ↓ vec3(st.x)      → 회색 배경
    ↓ plot(st)        → 선 마스크 pct ∈ [0,1]
    ↓ (1-pct)*배경 + pct*선색  → 블렌딩
gl_FragColor 출력
```

**셰이더의 핵심 사고방식 — "질문하기(Query-based)"**

일반 CPU 코드에서는 "선을 그려라"는 명령을 내린다. 셰이더에서는 반대다. 각 픽셀마다:

> "지금 내 픽셀이 선 근처인가? → 그렇다면 선 색으로, 아니라면 배경색으로"

이 사고방식이 셰이더 프로그래밍 전체를 관통하는 핵심 원리다.

## GLSL 문법 기초 — 전처리기·정밀도·Uniform

### 전처리기 분기

```glsl
#ifdef GL_ES
precision mediump float;
#endif
```

- `#ifdef GL_ES`: OpenGL ES / WebGL 환경에서만 아래 블록을 컴파일
- 데스크톱 OpenGL(GLSL 1.30+)에서는 `GL_ES`가 정의되지 않아 무시됨
- **크로스플랫폼 셰이더**의 표준 관용구

### 정밀도 한정자

| 한정자 | 근사 비트 | 용도 |
|---|---|---|
| `lowp` | ~8비트 | 색상 범위 0~1 — 최고 속도 |
| `mediump` | ~16비트 (half float) | 좌표, UV — 균형 |
| `highp` | 32비트 (IEEE 754) | 깊이, 정밀 계산 |

모바일 GPU에서 `precision mediump float` 누락 시 **색상 밴딩(banding)** 아티팩트 발생.

### Uniform 변수 — CPU에서 GPU로

```glsl
uniform vec2  u_resolution;  // 화면 해상도 — 모든 픽셀에서 동일
uniform vec2  u_mouse;       // 마우스 좌표 — 이 코드에서는 미사용
uniform float u_time;        // 경과 시간  — 이 코드에서는 미사용
```

`uniform` 변수는 하나의 Draw Call 동안 **모든 Fragment Shader 인스턴스가 동일한 값**을 공유한다. CPU에서 `glUniform*()` API로 설정되어 Constant Cache를 통해 GPU에 전달된다.

| 종류 | 키워드 | 픽셀마다 다른가 |
|---|---|---|
| **Uniform** | `uniform` | 아니오 |
| **인터폴레이티드** | `in` (구: `varying`) | 예 |
| **내장** | (없음) | 예 (`gl_FragCoord`) |

## GLSL 타입 시스템 — vec2 · vec3 · vec4

```glsl
vec2 st  = vec2(0.5, 0.3);       // (x, y)
vec3 col = vec3(1.0, 0.0, 0.0);  // RGB 빨강
vec4 out = vec4(col, 1.0);       // RGB + Alpha
vec3 gray = vec3(0.7);           // vec3(0.7, 0.7, 0.7) — 단일값 확장
```

**스위즐링(Swizzling)**: 성분을 자유롭게 조합·재배열

```glsl
// 아래 세 표현은 동일한 성분을 가리킴
// v.x 와 v.r 는 첫 번째 성분
// v.y 와 v.g 는 두 번째 성분
vec2 xy  = v.xy;    // 처음 두 성분
vec3 rev = v.zyx;   // 순서 반전
vec3 dup = v.rrr;   // 첫 성분을 세 번 복제
```

**생성자 오버로딩**:

```glsl
vec3 gray    = vec3(y);       // → vec3(y, y, y)
vec4 rgba    = vec4(gray, 1.0); // → vec4(r, g, b, 1.0)
```

## 좌표 정규화 — gl_FragCoord와 해상도 독립성

```glsl
vec2 st = gl_FragCoord.xy / u_resolution;
```

`gl_FragCoord`는 GPU의 Rasterizer(고정 기능 하드웨어)가 자동으로 공급하는 **픽셀 좌표** 내장 변수다.

$$st = \frac{gl\_FragCoord.xy}{u\_resolution} \in [0.0,\ 1.0]^2$$

| 위치 | 픽셀 좌표 (800×600) | 정규화 좌표 st |
|---|---|---|
| 왼쪽 하단 | (0.5, 0.5) | (0.000, 0.000) |
| 화면 중앙 | (400, 300) | (0.500, 0.500) |
| 오른쪽 상단 | (799.5, 599.5) | (0.999, 0.999) |

해상도가 바뀌어도 화면 중앙은 항상 `st = (0.5, 0.5)` → **해상도 독립적 셰이더** 작성 가능.

> [!warning] V축 방향 차이
> OpenGL: `st.y = 0` → 화면 **하단** / DirectX·Vulkan: `st.y = 0` → 화면 **상단**. UE5(HLSL)로 이식 시 `1.0 - v` 반전이 필요하다.

## plot() 함수 — SDF 방식 선 그리기

```glsl
float plot(vec2 st) {
    return smoothstep(0.02, 0.0, abs(st.y - st.x));
}
```

이 함수는 **SDF(Signed Distance Field) 방식**으로 직선 마스크를 생성한다.

### 3단계 분해

**① `st.y - st.x` — 직선 방정식 잔차**

직선 $y = x$는 $y - x = 0$과 동일하다. 임의 픽셀 $(x_0, y_0)$에 대해:

$$d = y_0 - x_0 \begin{cases} = 0 & \text{정확히 직선 위} \\ > 0 & \text{직선 위쪽} \\ < 0 & \text{직선 아래쪽} \end{cases}$$

**② `abs(st.y - st.x)` — 부호 없는 거리**

$$\text{dist} = |y_0 - x_0| \geq 0$$

절댓값을 취하면 선 위/아래 구분 없이 "선까지의 거리"만 남는다. 이것이 SDF의 핵심이다.

수학적으로 정확한 최단거리는 $\frac{|y-x|}{\sqrt{2}}$이지만, $\sqrt{2}$ 정규화를 생략하고 `smoothstep` 임계값으로 보정한다.

**③ `smoothstep(0.02, 0.0, dist)` — 소프트 마스크 생성**

edge0 > edge1이므로 출력이 반전된다:

| dist 값 | 출력 pct |
|---|---|
| 0.0 — 정확히 선 위 | 1.0 |
| 0.01 — 선 근처 | ~0.5 |
| 0.02 이상 — 선에서 멀리 | 0.0 |

**선 두께는 edge0 값으로 조절**:

| edge0 값 | 선 두께 효과 |
|---|---|
| 0.005 | 매우 얇은 선 |
| 0.02 | 기본 두께 |
| 0.1 | 두꺼운 선 |
| 0.5 | 화면 절반이 페더링 |

## smoothstep — S-곡선 보간의 수학

`smoothstep(edge0, edge1, x)`는 두 임계값 사이에서 0→1로 **부드럽게** 전환하는 Cubic Hermite 보간이다.

$$t = \text{clamp}\!\left(\frac{x - edge0}{edge1 - edge0},\ 0,\ 1\right)$$

$$\text{smoothstep} = t^2(3 - 2t)$$

경계 조건: $f(0) = 0, f(1) = 1, f'(0) = 0, f'(1) = 0$ — 경계에서 기울기가 0이므로 **경계가 부드럽게 연결**된다.

**`step` vs `smoothstep` 비교**:

```glsl
// step — 경계에서 딱 끊김 (앨리어싱 발생)
float hard = 1.0 - step(0.02, abs(st.y - st.x));

// smoothstep — 경계가 부드럽게 페더링 (서브픽셀 안티앨리어싱 효과)
float soft = smoothstep(0.02, 0.0, abs(st.y - st.x));
```

`smoothstep`이 GLSL에서 `if`보다 선호되는 이유: **Warp Divergence를 피하면서 안티앨리어싱을 동시에 달성**한다.

## 선형 보간과 블렌딩 — 셰이더의 합성 언어

```glsl
color = (1.0 - pct) * color + pct * vec3(0.0, 1.0, 0.0);
```

### lerp 공식

$$\text{result} = (1 - t) \cdot a + t \cdot b, \quad t \in [0, 1]$$

| pct 값 | 결과 |
|---|---|
| 0.0 | 배경색 그대로 |
| 0.5 | 배경색과 초록의 중간 |
| 1.0 | 순수 초록 |

이 코드는 GLSL 내장 `mix()` 함수와 완전히 동일하다:

```glsl
color = mix(color, vec3(0.0, 1.0, 0.0), pct);  // FMA 명령어 최적화
```

### Porter-Duff 알파 합성과의 연결

$$C_{out} = C_{src} \cdot \alpha + C_{dst} \cdot (1 - \alpha)$$

`pct`는 선 색의 **알파값**처럼 동작한다. 이 코드는 결국 "초록색 선 레이어를 배경 위에 반투명으로 합성하는 것"과 수학적으로 동일하다.

> [!success] "블렌딩을 마스터하라"는 말의 진짜 의미
> `(1-t)*a + t*b` 공식 하나가 다음 모든 것의 기반이다: PBR 레이어 혼합, Metallic-Diffuse 보간, 텍스처 합성, 마스크 기반 이펙트, UI 페이드. 이 공식의 주인이 되는 것이 셰이더 개발의 첫 번째 마스터리다.

## 하드웨어 구조와의 연결

```
[CPU]
    glUniform2f("u_resolution", w, h)  → Constant Cache
    glDrawArrays()                      → Draw Call 제출
         ↓ PCIe
[GPU]
    Rasterizer [Hardwired]
      → 삼각형을 Fragment로 변환
      → gl_FragCoord 자동 생성
         ↓
    SM (Streaming Multiprocessor)
      Shader Core × N: main() 병렬 실행
      Warp 단위 (NVIDIA: 32개, AMD: 64개) 동시 처리
      Constant Cache → u_resolution 빠르게 접근
         ↓
    ROP (Render Output Unit)
      gl_FragColor → Z-Test → Alpha Blending → Framebuffer(VRAM)
```

| 하드웨어 | 이 셰이더에서의 역할 |
|---|---|
| **CPU** | Uniform 값 설정, Draw Call 제출 |
| **PCIe 버스** | CPU → GPU 데이터 전송 |
| **Rasterizer** | 삼각형→Fragment 변환, gl_FragCoord 생성 |
| **Constant Cache** | u_resolution · u_mouse · u_time 고속 접근 |
| **Shader Core** | main() 병렬 실행 — 픽셀 수만큼 인스턴스 |
| **ROP** | gl_FragColor → Framebuffer 기록 |

이 코드는 텍스처 샘플링이 없으므로 순수 ALU(산술 논리 유닛) 연산만 수행한다. TMU(Texture Mapping Unit) 병목이 없어 매우 가볍다.

## [AI 생성 참고용] 셰이더 디자이너·그래픽스 엔지니어 연결점

> [!example] 관점 ① — SDF는 모든 도형의 공통 언어다
> 이 코드의 `abs(st.y - st.x)`는 직선 SDF의 최소 구현이다. 이 원리를 이해하면 원(`length(st-c) - r`), 사각형, 별, 캡슐 등 모든 도형을 동일한 패턴으로 표현할 수 있다. CSG 연산 — `min(d1,d2)` 합집합, `max(d1,d2)` 교집합, `max(d1,-d2)` 차집합 — 이 단순 수학으로 완성된다. Unreal Engine 머티리얼 그래프의 Custom 노드에서 SDF로 도형을 그리는 것이 포트폴리오에서 기술적 깊이를 증명하는 직접적 방법이다.

> [!example] 관점 ② — smoothstep은 무료 안티앨리어싱이다
> `smoothstep`으로 SDF 경계를 페더링하는 것은 MSAA나 TAA 없이 **서브픽셀 안티앨리어싱**을 달성하는 기법이다. 해상도 독립적으로 만들려면 `fwidth(dist)` (픽셀 단위 거리 변화량)를 동적으로 계산해 edge0으로 사용한다 — `smoothstep(fwidth(d), 0.0, d)` 패턴. 이 기법은 SDF 폰트 렌더링(Valve, SIGGRAPH 2007), UI 컴포넌트, 절차적 텍스처 전반에 사용된다.

> [!example] 관점 ③ — u_time으로 포트폴리오 퀄리티를 끌어올린다
> 이 코드의 `u_time`을 활용하면 정적 그라데이션이 살아있는 애니메이션이 된다. `y = 0.5 + 0.3 * sin(st.x * 6.2832 + u_time)`처럼 `plot()` 함수 하나로 사인 곡선, 포물선, 3차 곡선 등 다양한 함수 그래프를 실시간으로 그릴 수 있다. ShaderToy에 올린 이 결과물이 셰이더 디자이너 포트폴리오의 첫 번째 항목이 된다.

> [!example] 관점 ④ — Branchless Programming이 GPU 성능의 핵심이다
> GPU는 Warp(32개 스레드) 단위로 같은 명령을 실행한다. `if` 분기가 Warp 내에서 다른 경로를 타면 **Warp Divergence**로 성능이 절반 이하로 떨어진다. `smoothstep`, `step`, `clamp`, `mix`로 분기를 수학 연산으로 대체하는 **Branchless Programming** 패턴이 셰이더 최적화의 첫 번째 원칙이다. 이 코드가 `if (abs(st.y-st.x) < 0.02)` 대신 `smoothstep`을 쓰는 이유가 여기에 있다.

## Key Insights

> [!success] Insight 1 — "선을 그린다"에서 "픽셀에게 묻는다"로의 사고 전환
> 셰이더 프로그래밍은 CPU 프로그래밍과 사고방식이 근본적으로 다르다. CPU는 명령형(imperative) — "선을 그려라". 셰이더는 선언형(declarative) + 질문형(query) — "이 픽셀이 선에 가까운가?". 이 전환을 완전히 이해하면 ShaderToy의 복잡한 예제들이 모두 같은 패턴임을 알 수 있다. SDF로 형태를 정의하고, smoothstep으로 부드럽게 만들고, mix로 색을 섞는다.

> [!success] Insight 2 — smoothstep의 두 인자 순서가 모든 것을 결정한다
> `smoothstep(0.02, 0.0, dist)`에서 edge0 > edge1이면 출력이 반전된다. 선 거리가 0에 가까울수록 1을 반환하게 만드는 것이 이 반전의 목적이다. 이 패턴을 자유자재로 쓸 수 있으면 모든 SDF 기반 도형 렌더링이 가능하다.

> [!success] Insight 3 — `(1-t)*a + t*b` 공식이 셰이더의 합성 언어다
> 이 선형 보간 공식은 PBR에서 Metallic·Roughness 혼합, 레이어드 머티리얼, 마스크 기반 이펙트, 알파 합성까지 모든 셰이더 합성의 기반이다. GLSL `mix(a, b, t)`, HLSL `lerp(a, b, t)`, UE5 머티리얼의 `Lerp` 노드 — 모두 같은 공식의 구현이다.

> [!success] Insight 4 — 이 짧은 코드가 GPU 파이프라인 전체를 통과한다
> `gl_FragCoord` (Rasterizer 생성) → `u_resolution` (Constant Cache) → Shader Core에서 `main()` 병렬 실행 → `gl_FragColor` (ROP → Framebuffer). 단 20줄의 코드가 CPU·PCIe·Rasterizer·SM·ROP를 모두 거친다. 이 흐름을 이해하는 것이 렌더링 파이프라인 전체를 꿰뚫는 기반이 된다.
